Hardware
A single NVIDIA A100, L4 or T4 GPU; CCSD(T) reference on CPU.
Model access
An API key for the language model in the environment variable LLM_API_KEY; not needed for plain runs and rules runs.
Language model
A third-party service, not redistributed. The code reads the key from the environment and never prints it.

Steps

  1. Get the code. Download the source zip or read the files on Code.
  2. Open a notebook on a GPU machine and run the install cell. Restart the session if the installer asks you to.
  3. Quick wiring check. Set TOY_SIZE = "quick", TOY_MAX_MINUTES = 5 and RUN_MODE = "smoke", then run all cells. This takes minutes and checks that the calculator, the logger and the controllers are connected.
  4. Part A, the ammonia saddle test. A compact test with a known double-well potential, judged by an independent finite-difference Hessian.
  5. Part B, the step-cap sweep. A 150-gradient budget per run; finished runs are skipped when you run the notebook again.
  6. Compare with the logged runs on the data page: step counts, decisions and end points.
  7. The Hessian, NMR and property modules. Inputs and scripts are in the repository release.

Limit

These timings are single runs on shared cloud GPUs, for molecules of 16 and 19 atoms. They show that the workflow runs on such hardware. They are not a comparison of cost with other functionals.

Why a rerun may differ

Plain L-BFGS from a fixed start is deterministic in principle; on a GPU, small numerical differences can still change the outcome near a saddle point. The decisions of the language model depend on the model version and are not reproducible bit for bit, which is why every prompt, call and decision is logged. In the two repeated supervised runs the cap changes were the same at the same steps. Once the coordinates are fixed, no reported structure, frequency or shift depends on the model (section 5).

The model used in the runs of the Note was Google Gemini, called through its function-calling interface; see Design.
